Bulk Certificate Generator
A backend API that accepts bulk certificate generation requests, generatesPDF certificates from a predefined template, tracks per-certificate status,and serves the generated files for download.

Features
Bulk generation: one request handles many recipients
Background processing: requests return immediately with a job id (202)
Failure isolation: one invalid/failing recipient never blocks others
Live status tracking: job progress and per-certificate results
PDF download endpoint per certificate
Auto-generated interactive API docs (Swagger UI at /docs)
Tech Stack
Python 3.12+
FastAPI — HTTP framework
SQLAlchemy — ORM (SQLite by default; configurable via DATABASE_URL)
ReportLab — PDF rendering
pytest — test suite

API
1. Submit a certificate generation request
POST /api/certificate-jobs

{  "event_name": "AWS Cloud Practitioner Workshop",  "event_date": "2025-01-15",  "recipients": [    { "name": "Harish Ravikumar", "email": "harish@example.com" },    { "name": "Priya Sharma", "email": "priya@example.com" }  ]}
Response: 202 Accepted with the job resource (status: PENDING whilequeued).

2. Check job status / result
GET /api/certificate-jobs/{job_id}

Returns job status, progress counts, and per-certificate detail:

{  "id": "a3f8c2e9...",  "status": "COMPLETED",  "total_recipients": 2,  "completed_count": 2,  "failed_count": 0,  "pending_count": 0,  "certificates": [    {      "id": "b1d4...",      "recipient_name": "Harish Ravikumar",      "status": "COMPLETED",      "download_url": "/api/certificate-jobs/a3f8.../certificates/b1d4.../download"    }  ]}
3. Download a generated certificate
GET /api/certificate-jobs/{job_id}/certificates/{certificate_id}/download

Returns the PDF (application/pdf). Only COMPLETED certificates aredownloadable.

Design Decisions
Background processing over synchronous generation. A bulk request maycontain many recipients; generating all PDFs inside the request would makeclients wait (and time out) for large batches. The endpoint persists the job,enqueues process_job(job_id) via FastAPI BackgroundTasks, and returns202 Accepted immediately. Celery + a message broker would be the choice formulti-worker/multi-machine scale, but it adds infrastructure this servicedoesn't need yet — and since processing is an isolated service function(job_processor.process_job), swapping the executor later touches one line.

Per-certificate failure isolation. Each recipient gets its own databaserow, validated and generated inside its own try/except, committedindividually. Consequences:

One bad recipient becomes one FAILED row with a reason; all othercertificates in the job still complete.
Commits happen per certificate, so status polling shows live progress anda crash mid-job never loses completed work.
A job becomes COMPLETED even with partial failures — the per-certificatedata carries the full result.
Two-tier validation. Structural validation (Pydantic): if the payloaditself is malformed, the whole request is rejected with 422. Semanticvalidation (per recipient, in the processor): an invalid email fails onlythat recipient. Rejecting the entire bulk request because one of 500recipients is invalid would be the wrong contract.

UUID primary keys. Safe to expose in URLs (no enumeration), generated bythe application (no cross-environment collisions), and doubling as PDFfilenames.

Layered structure. routers/ (HTTP) → services/ (business logic) →models/ (persistence). The PDF generator is a pure function with no HTTP orDB knowledge — trivially unit-testable and reusable.

CRS-style note on correctness: measurements like"certificates generated so far" are derived from per-row state at read timerather than denormalized counters, so counts can never drift from reality.

Learning & Future Scope
What I took away from this project: designing an async job contract(202 + polling), isolating partial failures in bulk operations, and keepingHTTP, business logic, and persistence cleanly separated.

Future improvements:

Celery/Redis worker for horizontal scale and retries with backoff
Templated/custom certificate designs (the generator is already isolated)
Email delivery of certificates with deduplication
Object storage (S3) for generated files instead of local disk
Authentication + rate limiting on job submission
WebSocket/SSE live progress instead of polling
